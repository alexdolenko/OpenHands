# Changelog - 17-09-2026, V. 1.20.1

**Release Date**: 17-09-2026 at 20:30
**Version**: 1.20.1 (previously 1.20.0)
**Object**: fix(conversation): tolerate malformed records in the conversation list (#17497)
**Code review**: `docs/3-code-review/CR_v1.20.1.md` (Codex loop, 3 rounds + SHA re-anchor -> APPROVED with observations)

## Changes

- Conversation **search/list** parsing is now tolerant of individual malformed
  records. A single corrupt conversation no longer blanks the entire history
  list (#17497): `toResilientConversationPage` validates and converts each raw
  item in its own try/catch, logs `Skipping malformed conversation at index N
  (id: X): <error>` and drops the bad record, keeps the rest, preserves the
  planner-parent filter, and still throws on a non-array/non-record page shape.
- The catch spans **both** validation (`requireDirectConversationInfo`) and
  conversion (`toAppConversation`, which can throw via `combineUsageMetrics` on
  malformed `stats`), so a valid-id record with bad stats no longer blanks the
  list either.
- Single-conversation and batch paths stay **strict** — opening one corrupt
  conversation still surfaces its error rather than resolving to `null`.
- Systemic `NoBackendAvailableError` (active backend removed mid-search) is
  rethrown, not swallowed, so it never masquerades as an empty result.
- Removed the now-unused `requireConversationSearchPage` and the service's
  unused `toConversationPage` import.
- 9 regression tests added; cloud, adapter, and batch/single paths unchanged.

## Roads not taken

- **User-facing "N conversations couldn't be loaded" notice** — deferred to a v2
  (list UI + i18n); tracked in `docs/1-plans/BACKLOG.md`. v1 is console-only
  drop+warn, the smallest change that restores a working list.
- **Wrapping the batch/single path too** — rejected: it would mask a corrupt
  single-conversation open as "not found"; only the list path is tolerant.
